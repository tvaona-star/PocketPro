# 1. Product Overview
PinPal established the category. Pocket Pro improves every layer of it: a faster entry flow, modern stats modeled on PBA broadcast presentation, and the most complete ball and layout management system in any bowling app.
Equipment positioning: Pocket Pro is the definitive equipment record for a competitive bowler â€” ball specs from manufacturer databases, full layout library across all major drilling systems, drilling specs, surface prep history, bag builder, and arsenal charting. TenPin Toolkit remains the tool of choice for pre-shot physical game analysis (angles, targeting, axis tilt measurement). The two apps are complementary, not competing.
The iOS codebase is built with platform-agnostic architecture (SwiftUI + clean data layer) so Android (Kotlin/Jetpack Compose) is a port, not a rewrite in v2.

# 2. Goals & Non-Goals
### Goals
- Frame-by-frame stat entry for every game, grouped by session type
- PBA broadcast-style stat dashboard: strike %, spare % by type, split frequency, open frame rate, clean game rate, streak tracking
- Complete ball arsenal: specs from manufacturer databases, per-weight storage, surface prep history, performance notes by pattern type
- Full layout system: personal layout library, Dual Angle and VLS support, drilling specs, one active layout per ball, layout history
- Bowler profile: PAP stored centrally, referenced throughout arsenal and layout tools
- Arsenal chart: configurable scatter plot of all balls on any two spec axes
- Bag builder: league, tournament, and practice bags with named variations
- Ball comparison: any two balls, all specs side by side, diffs highlighted
- iOS-first, Android-ready architecture
### Non-Goals (v1)
- Angles and targeting visual tool â€” TenPin Toolkit
- Axis tilt and rotation measurement â€” TenPin Toolkit
- Ball speed and RPM video measurement â€” TenPin Toolkit (v2+ consideration)
- Layout recommendation engine â€” v3+ consideration
- Auto score sync from lane systems
- Social features or public leaderboards
- Android native app (architecture supports it â€” v2 target)

# 3. User Personas
### The Serious League Bowler
- Averages 170-220+, bowls 1-3 nights per week in sanctioned leagues
- Owns 4-8 balls, tracks surface and layout deliberately
- Wants to know: 'Am I missing more 10-pins than I used to? Is this ball still at the right surface?'
### The Tournament Competitor
- Bowls USBC, PBA Regional, or local open events on sport and challenge conditions
- Carries 6-8 ball tournament bags, needs layout and drilling records per ball
- Reviews sessions to evaluate ball sequencing, line decisions, and equipment performance
### The Practice-Focused Developer
- Works with a coach, tracks specific mechanics goals per session
- Logs practice sessions separately from league â€” doesn't want them polluting league stats
### The Recreational Bowler (Secondary)
- Averages 100-160, bowls once a week casually
- Wants a clean scorecard and basic stats â€” app must not front-load equipment complexity

## 5.5.3  Leave Classifier Engine
The classifier runs automatically when frame pin counts are entered. All 1,023 combinations are pre-classified at build time into a local lookup table â€” no runtime calculation required.
- Pin configuration stored as a sorted array of standing pin numbers (e.g., [3, 6, 10] for a 3-6-10 leave)
- Lookup table maps every pin combination to its resolved category tag array â€” built and validated before v1 ships
- Priority rules applied at build time â€” lookup table stores final resolved tag set per combination
- Named leaves hardcoded as exact-match entries; category rules cover all remaining combinations
- PinPal import: all imported frame data re-processed through classifier so historical spare data receives full category tagging
- Manual override: bowler can tap any frame leave and override the auto-assigned category â€” override stored on that SpareLeave record
## 5.5.4  Spares Tab Views
### Corner Pin Spotlight
7-pin and 10-pin always visible at the top of the Spares tab without scrolling â€” the two most important single spares for a competitive bowler. Each shows: times left this season, conversion %, trend vs. prior period (arrow + delta).
### Leave Frequency List
Default view. Sorted by frequency (most common leave at top). Each row shows:
- Pin diagram â€” visual representation of the exact leave configuration
- Leave name if it has one (e.g., 'Bucket', '7-10', 'Baby Split') â€” pin numbers otherwise (e.g., '4-6-9')
- Category badge â€” the primary category tag
- Times left â€” count and % of frames
- Times converted â€” count and conversion % â€” color coded: green (80%+), amber (50-79%), red (under 50%)
- Tapping any row opens a full leave detail: every frame it occurred, date, session, game, frame note if logged
### Pin Leave Heatmap (v1.5)
Alternate view toggled alongside the list. Pin deck displayed with each of the 10 pin positions color-coded by how frequently that pin appears in any leave â€” red = left often, green = rarely left. Tapping a pin position filters the leave list to only leaves containing that pin. Gives an instant visual read on which pins are the problem.
### Category Filter
Filter chips across top of the leave list: All / Single Pins / Corner Pins / Sleepers / Clusters / Washouts / Baby Splits / Splits / Big Splits / Buckets / Big Four / 7-10 / Other. Selecting a category filters the leave list to only matching combinations.
### Filters
- Session type (League / Tournament / Practice / Misc / All)
- Date range
- Ball used â€” to identify if a specific ball correlates with more leaves of a certain type
### Miss Log
Chronological list of all unconverted spare attempts. Each row: date, session type, leave name or pin combo, frame number. Tapping opens that session in the Sessions tab at the relevant frame.

## 7.3  Motion and Interaction
- Expand/collapse: spring animation on section cards â€” fast (0.25s), not bouncy
- Bottom sheets: slide up from bottom, spring dismiss. Never full-screen modal for entry flows that can be done in a sheet

## 7.4  Empty States
Empty states are never just a message. Every empty state tells the bowler exactly what to do next and why it matters.

- Layout Library â€” empty: 'Create a layout to assign to your balls.' + New Layout button
- Stats â€” not enough data: tiles display '--' rather than zero. A note below: 'Bowl more sessions to populate your stats.' Threshold: 5 games minimum before stats display
## 7.5  Core UX Rules
### Two Taps to Any Primary Action
New session: 1 tap. Log a frame: 1 tap. Session note: 1 tap. Ball detail: 1 tap from list. Layout library: 1 tap from Arsenal tab. If a primary action requires 3+ taps, the flow needs redesign.
### One-Handed Entry at the Lanes
Bottom sheet patterns, large tap targets (minimum 44pt), all interactive elements in the lower two-thirds of the screen during active scoring. No small toggles or tiny inputs when bowling.
### Depth Is Earned, Not Imposed
Casual bowlers see scores, basic stats, and a note field. Equipment depth unlocks naturally as the bowler adds balls, layouts, and sessions. The app never asks for data it doesn't need yet.
### Bowling-Native Language and Notation
Layouts display as bowlers write them: 50Â° x 4 3/4" x 40Â°. Specs display as bowlers read them: RG 2.48, Diff 0.051. Leave names match what bowlers say: '10 pin', 'baby split', 'big four' â€” not 'pin configuration 7-10' or 'split type B'.
### Stats Read Like a Broadcast
Every stat tile is a large number with a small label below it and a trend indicator beside it. Color carries meaning: green is good, amber is watch it, red is a problem. No pie charts. No stacked bar graphs. If it wouldn't fit in a PBA scorebug, reconsider it.
### The Layout Library Is a Reference Card, Not a Form
Layouts are named, saved, and selected â€” like picking from a physical reference card at the pro shop. Assigning a layout to a ball should take one tap after the layout library is populated. Creating a new layout is the only time the form appears.

## 13.4  Import Integrity Rules
- Frame data: if a PinPal game has incomplete frame data (PinPal allows final-score-only entry), the game is imported with the final score stored and frame data marked as unavailable. These games are excluded from spare tracking stats but included in average and score history
- Duplicate detection: if an imported session exactly matches an existing session (same date + location + scores), the bowler is shown both records and asked to keep one or both
- Ball name matching: if an imported ball name exactly matches a ball already in the Pocket Pro arsenal (case-insensitive), the import links to that existing ball rather than creating a duplicate shell record
- Re-import safety: running the import again with the same CSV does not create duplicates â€” the import detects previously imported records by a hash of the source data
